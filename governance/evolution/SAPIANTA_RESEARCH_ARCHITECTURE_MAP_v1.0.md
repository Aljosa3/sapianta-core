# SAPIANTA_RESEARCH_ARCHITECTURE_MAP_v1.0

Status: ARCHITECTURAL SPECIFICATION  
Layer: L3 Governance  
Scope: Autonomous Research System  
Version: 1.0


------------------------------------------------------------
1. PURPOSE
------------------------------------------------------------

This document describes the complete architecture of the
SAPIANTA Autonomous Research System.

The Research System is responsible for:

• discovering new ideas
• testing hypotheses
• generating knowledge
• evolving strategies
• promoting validated artifacts into operational domains

The architecture ensures that research remains:

• deterministic
• traceable
• governance-compliant
• separated from runtime execution


------------------------------------------------------------
2. HIGH LEVEL ARCHITECTURE
------------------------------------------------------------

The research system operates as a closed learning loop.

INFORMATION SPACE
↓
Idea Discovery Engine
↓
Idea Registry
↓
Idea Validator
↓
AI Software Factory (ASF)
↓
Experiment Pipeline
↓
Artifact Registry
↓
Knowledge Engine
↓
Promotion System
↓
Domain Integration
↓
Decision Spine
↓
Execution
↓
World State


------------------------------------------------------------
3. IDEA DISCOVERY ENGINE
------------------------------------------------------------

Responsible for discovering potential improvements.

Sources:

• research papers
• GitHub repositories
• technical blogs
• forums
• market data
• domain data streams

Agents:

• LLM research agents
• web crawlers
• repository analyzers
• domain intelligence agents

Output:

IDEA_ARTIFACT


------------------------------------------------------------
4. IDEA REGISTRY
------------------------------------------------------------

The Idea Registry stores discovered ideas.

Properties:

• append-only storage
• domain classification
• traceable origin
• timestamped entries


------------------------------------------------------------
5. IDEA VALIDATION
------------------------------------------------------------

Each idea must pass governance validation before entering
the research pipeline.

Validation checks:

• architecture compatibility
• domain relevance
• feasibility assessment
• governance compliance


------------------------------------------------------------
6. AI SOFTWARE FACTORY (ASF)
------------------------------------------------------------

ASF converts validated ideas into executable experiments.

Responsibilities:

• hypothesis generation
• experiment configuration
• experiment code generation
• dataset selection
• metric definition


------------------------------------------------------------
7. EXPERIMENT PIPELINE
------------------------------------------------------------

Experiments evaluate hypotheses generated by ASF.

Process:

hypothesis
↓
experiment execution
↓
metric evaluation
↓
experiment artifact


Artifacts produced:

EXPERIMENT_ARTIFACT


------------------------------------------------------------
8. ARTIFACT REGISTRY
------------------------------------------------------------

All experiment results are stored in the Artifact Registry.

Artifact types:

• models
• strategies
• parameters
• evaluation metrics
• experiment artifacts


------------------------------------------------------------
9. KNOWLEDGE ENGINE
------------------------------------------------------------

Analyzes experiment results to extract patterns.

Functions:

• ranking strategies
• identifying parameter sensitivity
• discovering performance regimes
• generating insights

Outputs:

• knowledge artifacts
• new idea artifacts


------------------------------------------------------------
10. PROMOTION SYSTEM
------------------------------------------------------------

The Promotion System evaluates whether research artifacts
should be promoted to operational domains.

Promotion conditions:

• reproducible results
• performance above baseline
• governance compliance

Promotion produces:

PROMOTION_ARTIFACT


------------------------------------------------------------
11. DOMAIN INTEGRATION
------------------------------------------------------------

Promoted artifacts are integrated into domain modules.

Example:

Trading domain → candidate strategy

Domain integration produces:

PROPOSAL_ARTIFACT


------------------------------------------------------------
12. DECISION SPINE
------------------------------------------------------------

All operational decisions must pass through the Decision Spine.

Process:

proposal
↓
policy validation
↓
decision envelope
↓
ledger recording


------------------------------------------------------------
13. SAFETY PRINCIPLE
------------------------------------------------------------

The research system must never directly execute real-world actions.

All operational actions must pass through:

policy validation
decision envelope
ledger
