# v0.20 — KERNEL LOCK
## Product-Grade AI Kernel

Status: LOCKED  
Applies to: Core Kernel Only  
Effective from: v0.20

---

## 1. NAMEN ZAKLEPA

Ta dokument formalno in nepreklicno zaklene **Product-Grade AI Kernel** sistema v fazi **v0.20**.

Zaklep pomeni:
- konec arhitekturnega eksperimentiranja
- konec semantičnih sprememb jedra
- začetek uporabe jedra kot **stabilne platforme**

Po tem dokumentu se jedro obravnava kot:
> stabilen, nadzorovan in odgovoren sistemski temelj

---

## 2. OBSEG ZAKLEPA

Zaklep velja za:

- execution semantics
- guard lifecycle arhitekturo
- observability pipeline
- learning governance mehanizme
- decision boundary definicije
- kernel ↔ module interface (contractual)

Zaklep **ne velja** za:
- uporabne (use-case) module
- konfiguracije znotraj dovoljenih policyjev
- parametrične prilagoditve, ki ne spreminjajo semantike

---

## 3. DOVOLJENE SPREMEMBE PO ZAKLEPU

Po zaklepu so dovoljene **izključno** naslednje spremembe:

### D1 — Bug Fixes
- popravek napak
- brez spremembe vedenja
- brez spremembe odločitev

### D2 — Performance Improvements
- optimizacije
- refaktorji brez semantičnega vpliva

### D3 — Observability Enhancements
- dodatni logi
- boljša sledljivost
- boljši kontekstni zapisi

Vsaka sprememba mora biti:
- lokalna
- reverzibilna
- dokumentirana

---

## 4. PREPOVEDANE SPREMEMBE

Po zaklepu so **strogo prepovedane**:

- spremembe decision flow logike
- spremembe guard semantike
- spremembe learning pravil
- razširjanje privilegijev kernel API-ja
- implicitno vplivanje modulov na kernel

Vsaka taka sprememba pomeni:
> **kršitev zaklepa (Kernel Breach)**

---

## 5. RAZMERJE DO FAILURE ACCEPTANCE CRITERIA

Ta zaklep je neposredno vezan na dokument:

- `governance/specs/v0.20_FAILURE_ACCEPTANCE_CRITERIA.md`

Če pride do:
- U1–U5 failure

je ta zaklep:
- začasno suspendiran
- sistem se vrne v redesign fazo
- zahteva nov version tag

---

## 6. POSLEDICE ZAKLEPA

Z zaklepom v0.20:

- se lahko začne razvoj uporabnih modulov
- se lahko vzpostavi use-case track (v1.x)
- se kernel obravnava kot zaupanja vreden sistemski sloj

Brez tega dokumenta:
- v0.20 ni formalno zaključena

---

## 7. OBVEZNA IZJAVA

Z zaklepom v0.20 sistem formalno potrjuje:

> “Kernel is locked not because it is immutable,
> but because it is accountable.”
