# SAPIANTA — Phase v0.10 OBSERVABILITY SCHEMA
## Canonical Schema for Execution Observability & Deterministic Introspection

Status: SCHEMA
Phase: v0.10
Depends On:
- v0.10-INIT-LOCKED
- v0.10-STRUCTURAL
Modifies Runtime Behavior: NO
Introduces Autonomy: NO
Introduces Interpretation: NO

---

## 1. Purpose of This Schema

This document defines the **canonical schema** for all observability artifacts introduced in Phase v0.10.

The schema specifies:
- what kinds of records exist,
- what fields they may contain,
- how records are categorized,

and explicitly does **not** define:
- processing rules,
- evaluation logic,
- interpretation,
- ordering semantics beyond declaration,
- causality.

This schema exists solely to ensure **structural determinism** and **semantic immutability**.

---

## 2. Canonical Principles

All schema elements in v0.10 adhere to the following principles:

- Observational only
- Fact-preserving
- Non-evaluative
- Non-reactive
- Side-effect free
- Deterministic in structure

No field defined in this schema may:
- encode decisions,
- imply intent,
- suggest correctness or failure,
- trigger behavior.

---

## 3. Execution Event Record

### Record Type
`ExecutionEvent`

### Description
A factual record that an execution-related event occurred.

### Required Fields
- event_id  
- execution_id  
- event_type  
- timestamp  

### Optional Contextual Fields
- phase_reference  
- runtime_mode_label  
- source_reference  

### Constraints
- event_type is a categorical label, not a semantic judgment
- timestamps are descriptive, not ordering authorities
- no event implies success or failure

---

## 4. Execution Event Types

### Canonical Category
`ExecutionEventType`

### Allowed Values (Closed Set)
- ExecutionStarted
- ExecutionStepEntered
- ExecutionStepExited
- ExecutionCompleted
- ExecutionAborted

### Constraints
- The set is closed for v0.10
- No subtype inference is allowed
- Event types do not encode cause or outcome quality

---

## 5. Execution State Snapshot Record

### Record Type
`ExecutionStateSnapshot`

### Description
An immutable snapshot of execution state at a declared boundary.

### Required Fields
- snapshot_id  
- execution_id  
- snapshot_label  
- timestamp  

### Optional Fields
- state_descriptor  
- structural_context_reference  

### Constraints
- Snapshots are not compared
- Snapshots do not imply deviation
- Snapshots do not encode transitions

---

## 6. Execution Context Descriptor

### Record Type
`ExecutionContextDescriptor`

### Description
A static descriptor binding execution to declared contextual labels.

### Fields
- execution_id  
- phase_id  
- runtime_mode_label  
- canonical_source_id  

### Constraints
- All fields are labels
- No field may be treated as a parameter
- Context descriptors do not affect execution behavior

---

## 7. Guard Outcome Record

### Record Type
`GuardOutcomeRecord`

### Description
A factual record of a guard lifecycle outcome relevant to execution.

### Required Fields
- guard_id  
- execution_id  
- outcome_label  
- timestamp  

### Constraints
- outcome_label is treated as an external fact
- No inference of causality is allowed
- Guard outcomes do not imply correctness of execution

---

## 8. Audit Enrichment Record

### Record Type
`AuditEnrichment`

### Description
A structural augmentation to an existing audit entry.

### Allowed Fields
- execution_id  
- phase_reference  
- structural_timestamp  

### Constraints
- Audit authority remains unchanged
- Enrichment is append-only
- No enrichment alters audit meaning

---

## 9. Introspection Artifact Record

### Record Type
`IntrospectionArtifact`

### Description
A registry entry representing a produced observability artifact.

### Required Fields
- artifact_id  
- artifact_type  
- execution_id  
- creation_timestamp  

### Constraints
- artifact_type is categorical
- No prioritization or scoring
- Registry is non-interactive

---

## 10. Explicit Schema Exclusions

The following are explicitly excluded from this schema:

- Derived metrics
- Scores or ratings
- Aggregations
- Heuristics
- Probabilistic fields
- Decision flags
- Control indicators
- Feedback markers

Any such field requires a **new phase INIT**.

---

## 11. Schema Closure Statement

This schema defines the **complete and exclusive observability vocabulary** for Phase v0.10.

No additional record types, fields, or values may be introduced without:
- a new phase INIT, and
- an explicit scope authorization.

END OF DOCUMENT
