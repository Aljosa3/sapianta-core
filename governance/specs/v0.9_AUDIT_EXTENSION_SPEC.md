# SAPIANTA — v0.9 AUDIT EXTENSION SPEC
## Status: DRAFT (Phase v0.9)

## Purpose
This specification extends the audit model to **include execution semantics**
introduced in v0.9, without altering audit authority, interpretation, or behavior.

The audit layer remains **passive, append-only, and non-interpreting**.

## Normative Context
This document operates strictly under:
- SCF v0.4 (Execution Boundary & Guard Lifecycle)
- v0.8 Audit Trace Specification
- v0.9 Execution Semantics Specification

No rule herein may modify Guard authority or runtime behavior.

## Core Invariant
> **Audit records facts; it never explains, evaluates, or summarizes them.**

## Audit Record Extension
Each execution audit record SHALL include the following **additional fields**:

### Required Fields
- `execution_semantic`  
  - Type: ENUM (as defined in v0.9 EXECUTION SEMANTICS SPEC)
  - Source: Guard-assigned
  - Mutability: Immutable

- `semantic_assigned_by`
  - Identifier of the Guard context that assigned the semantic
  - Read-only

- `semantic_assigned_at`
  - Timestamp of semantic assignment
  - Read-only

## Preservation Rules
- Audit MUST record semantic values **verbatim**.
- Audit MUST NOT:
  - infer meaning
  - collapse categories
  - attach explanations
  - derive conclusions
- Audit entries MUST remain immutable once written.

## Temporal Integrity
- Semantic data MUST be recorded at the same logical time as the execution event.
- No post-hoc enrichment or correction is permitted.

## Prohibited Extensions
Audit extensions MUST NOT:
- introduce aggregate fields
- compute statistics
- classify executions
- assign severity, confidence, or intent
- reference future or external state

Any such behavior constitutes a **violation of v0.9 scope**.

## Backward Compatibility
- Pre-v0.9 audit records remain valid.
- Absence of `execution_semantic` in historical records SHALL NOT be interpreted.

## Forward Compatibility
- Any additional audit fields related to semantics require:
  - a new phase INIT
  - explicit boundary specification
  - LOCK prior to usage

## Exit Criteria
This specification is complete when:
- Semantic fields are defined and immutable
- Audit behavior remains unchanged
- No interpretive logic is introduced

## Phase Guarantee
Upon completion of v0.9:
- Audit traces are semantically enriched
- Audit authority remains unchanged
- No semantic interpretation occurs
