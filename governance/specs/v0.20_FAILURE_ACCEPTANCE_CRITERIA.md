# v0.20 — FAILURE ACCEPTANCE CRITERIA
## Product-Grade AI Kernel

Status: DRAFT → LOCK after v0.20 validation  
Scope: Kernel-only (excludes use-case modules)

---

## 1. NAMEN DOKUMENTA

Ta dokument definira **dopustne oblike odpovedi (failure modes)** sistema v fazi **v0.20 Product-Grade AI Kernel** ter določa:

- katere vrste napak so **sprejemljive**
- katere pomenijo **neuspeh faze v0.20**
- katere sprožijo **obvezen redesign ali rollback**

Dokument preprečuje napačno interpretacijo v0.20 kot “popolnosti”.

---

## 2. TEMELJNO NAČELO

> v0.20 **ni** faza brez napak.  
> v0.20 je faza, kjer so **napake omejene, razložljive in obvladljive**.

Vsaka napaka mora biti:
- zaznana
- razložena
- lokalizirana
- reverzibilna

Če kateri od teh pogojev odpove → failure is **NOT acceptable**.

---

## 3. SPREJEMLJIVE OBLIKE ODPOVEDI (ACCEPTABLE FAILURES)

### A1 — Use-Case Mismatch
Opis:
- Kernel pravilno deluje
- a se izkaže, da:
  - API ni optimalen za določen use-case
  - potrebna je dodatna abstrakcija

Status:
- ACCEPTABLE

Ukrep:
- refactor interface layer
- kernel core ostane nespremenjen

---

### A2 — Over-Constrained Kernel
Opis:
- kernel je preveč restriktiven
- uporabni moduli zahtevajo:
  - preveč obvodov
  - nerodno delo s policyji

Status:
- ACCEPTABLE

Ukrep:
- sprostitev pravil
- dokumentiran policy redesign
- brez odstranitve guardov

---

### A3 — Guard False Positives
Opis:
- Guard Lifecycle preveč pogosto blokira legitimne akcije

Status:
- ACCEPTABLE

Ukrep:
- guard tuning
- threshold adjustments
- dodatni context signals

---

### A4 — Performance Inefficiency
Opis:
- sistem je pravilen
- a prepočasen ali predrag

Status:
- ACCEPTABLE

Ukrep:
- optimizacija
- caching
- arhitekturni tuning

---

## 4. NESPREJEMLJIVE OBLIKE ODPOVEDI (UNACCEPTABLE FAILURES)

### U1 — Unexplainable Outcome
Opis:
- kernel izvede odločitev
- ni mogoče rekonstruirati:
  - zakaj
  - na podlagi česa
  - v katerem kontekstu

Status:
- NOT ACCEPTABLE

Ukrep:
- takojšnja ustavitev rollouta
- redesign observability ali decision pipeline

---

### U2 — Guard Bypass (Explicit or Implicit)
Opis:
- uporabni modul:
  - obide guard
  - ali inducira odločitev brez guard evaluation

Status:
- NOT ACCEPTABLE

Ukrep:
- kernel breach
- obvezen redesign execution boundary

---

### U3 — Non-Reversible Learning Effect
Opis:
- učenje povzroči spremembo,
- ki je ni mogoče:
  - razveljaviti
  - zamrzniti
  - lokalizirati

Status:
- NOT ACCEPTABLE

Ukrep:
- freeze learning
- rollback model state
- redesign learning governance

---

### U4 — Cross-Module Contamination
Opis:
- en modul vpliva na drugega
- brez eksplicitne odobritve

Status:
- NOT ACCEPTABLE

Ukrep:
- takojšnja izolacija
- redesign module sandboxing

---

### U5 — Normative Drift
Opis:
- sistem se začne obnašati v nasprotju z:
  - definiranimi policyji
  - guard intentom
  - governance dokumenti

Status:
- NOT ACCEPTABLE

Ukrep:
- kernel invalidated
- vrnitev v pre-v0.20 fazo

---

## 5. KRITERIJ USPEŠNO ZAKLJUČENE v0.20 FAZE

v0.20 se šteje za uspešno zaključeno, če:

- ni zaznan noben U1–U5 failure
- vsi A1–A4 failure so:
  - dokumentirani
  - lokalno rešeni
- obstaja:
  - jasna meja kernel ↔ moduli
  - možnost izklopa posameznega modula
  - možnost zamrznitve učenja

---

## 6. OBVEZNA IZJAVA OB ZAKLEPU

Ob zaklepu v0.20 mora obstajati izjava:

> “Kernel is considered product-grade not because it is perfect,
> but because all known failure modes are observable, bounded,
> and governable.”

---

## 7. RAZMERJE DO NADALJNJIH FAZ

- v1.x use-case moduli **ne smejo** spreminjati teh kriterijev
- vsak kernel redesign mora:
  - ponovno prestati ta dokument
  - imeti nov version tag
